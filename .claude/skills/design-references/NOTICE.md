# Source

The `DESIGN.md` files under `design-md/` are vendored verbatim from
[voltagent/awesome-design-md](https://github.com/voltagent/awesome-design-md)
(commit `8147538b4226ae41e2487a9179e3bcc1f68e8554`), MIT licensed. Each file
is that repo's own extracted analysis of a specific company's public
website -- not sourced or re-derived here.

Per-brand `README.md` stubs from the upstream repo were not vendored --
each one is five lines pointing to getdesign.md with no content of its
own; `DESIGN.md`'s own frontmatter description and Overview section
already cover what the stub would.

## Curation

Upstream has 70+ brands spanning automotive (Ferrari, Bugatti, Lamborghini,
BMW), consumer lifestyle (Nike, Starbucks), retro/gaming (Nintendo-2001,
Dell-1996, PlayStation), and media (The Verge, Wired) alongside the SaaS/
fintech/dev-tool brands. Only the 14 that share Rekono's own genre --
B2B SaaS, fintech, and developer-tool marketing -- were vendored; the rest
have no plausible bearing on an invoice-automation product's marketing
site and would just be repo clutter. See `SKILL.md`'s table for which 14
and why each was picked.

Check upstream periodically for updates or newly-added relevant brands;
this copy will not update itself.

## Policy reminder

See `SKILL.md` for the full policy. In short: these are reference material
for design *principles*, never a source of tokens to copy into Rekono's
own site. Closely mimicking a specific named company's exact design
system is a materially different (and worse) outcome than being informed
by how a well-regarded product handles a specific problem.
